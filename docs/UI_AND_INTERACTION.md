# UI 与交互规范

LukePanel 使用同一套响应式设计系统覆盖登录、概览、系统、Docker、文件、工具、GitHub、审计和安全页面。新增或修改页面时必须遵循以下约束。

## 响应式布局

- 页面不能依赖固定屏幕宽度；320px 到桌面宽度均不得出现页面级横向滚动。
- 手机端表单控件字号不得低于 16px，避免 iOS Safari 聚焦缩放。
- 固定底部导航只出现在顶层页面；子页面、编辑器、对话框和底部弹层打开时必须隐藏。
- 长路径、URL、镜像名、仓库名和软件包名必须换行或截断，不能撑破卡片。
- 页面主操作、危险操作和次要操作需要明确视觉层级，不能只依赖颜色表达状态。

## 键盘与对话框

- 输入型对话框以 `window.visualViewport` 的实时高度和偏移定位。
- 键盘打开时，标题、输入框、错误信息与确认按钮必须同时保留在可视区域内。
- 打开覆盖层时锁定背景滚动，关闭后恢复原页面位置。
- 表单支持回车提交，取消操作必须可见且不会触发写入。

## 真实交互

- 每个可见按钮必须绑定真实事件处理器；没有后端能力的功能不得渲染成可点击按钮。
- 每个前端 API 请求必须对应真实服务端路由。
- 功能开关的文案必须描述真实行为。例如 GitHub 助手属于内置功能，开关只能描述“显示/隐藏入口”，不能称为安装或卸载。
- 后台任务必须返回真实任务状态、日志和结果，不能用前端计时器伪造进度。
- 失败必须展示服务端返回的实际错误；成功提示只能在服务端确认完成后出现。

## 危险操作

- 删除、覆盖、权限、账户、SSH、防火墙、软件升级等操作需要明确确认。
- 需要近期密码验证的操作使用统一二次验证流程。
- 能够快照、备份或回滚的操作应在执行前完成保护步骤。
- 禁止在浏览器中提供任意 root Shell 输入。

## 自动检查

发行版本至少需要通过：

```bash
make frontend
go test ./...
go vet ./...
go test -race ./...
node --check web/app.js
```

前端契约测试会检查无处理器按钮、占位交互、静态 API 路径、品牌资源和关键移动端规则。
## 信息层级与状态

- 概览页只展示会影响判断或下一步操作的信息；禁止为了填满卡片而重复同一状态。
- 状态必须来源于后端实际检测。无法确定时应说明检测来源和缺失原因，不能只显示“未知”。
- NTP 必须区分服务是否安装、服务是否运行、系统时钟是否同步；内核优化必须同时显示管理预设与实际生效参数。
- 列表页优先使用紧凑行，操作收纳到明确的详情页或操作面板，避免把所有按钮平铺成标签云。
- 桌面端使用侧栏和内容区，移动端只保留五个一级入口；二级页面不重复显示底部导航。

## 视觉基准

- 桌面端：深色侧栏、浅色内容区、清晰的状态与操作分区。
- 移动端：单列信息流、紧凑卡片、至少 44px 触控区域、16px 输入控件字号。
- 卡片圆角、边框、阴影、留白和按钮高度必须来自统一设计变量，不允许单页自行定义相近但不同的尺寸。
- 发行前至少检查 320px、375px、390px、430px 和桌面 1440px 宽度。
