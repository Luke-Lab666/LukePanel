1. Web/Agent 防火墙新增与删除请求采用嵌套协议；

3. 完整应用与回滚恢复原文件；

5. 生成的 Go 防火墙测试在 Go 1.23.2 下实际编译并运行。

UFW 参数组合覆盖：

- `allow in ... proto tcp`
- `deny out from CIDR ... proto udp comment ...`
- `reject in ...` + 任意协议端口范围

## 人工截图复核

人工检查了 320px 手机安全中心、390px iPhone 概览、320px 文件管理、844×390 横屏弹窗和 1440px 桌面安全中心。

人工复核发现并修复了一个自动检测没有判错的细节：桌面端防火墙规则采用双列时，较窄卡片可能截断端口文字。最终改为稳定单列规则卡片，并重新执行全部 88 次浏览器回归，结果仍为零失败。

## 故障安全

- 应用前严格检查原始代码锚点；
- 修改前生成带时间戳的逐文件备份；
- `go test`、`go vet`、JS 语法或资源一致性任一失败即自动回滚；
- 支持独立 `rollback.sh` 手动恢复；
- 不直接执行不受控 Shell 命令，不放宽 Agent 权限边界。

## 未在当前沙箱执行的项目

1. **真实 UFW 变更**：实际执行会修改宿主机防火墙并可能影响连接，因此当前环境只验证命令参数生成、错误内容和 Agent/Web 契约。
2. **原仓库完整编译**：GitHub App 写入返回 403，容器无法直接取得仓库归档；迁移器针对从 GitHub 读取并核对的真实源码锚点构建。`apply.sh` 在用户的完整源码上会执行 `go test ./...` 和 `go vet ./...`，失败自动回滚。
3. **真实生产数据操作**：Docker 删除、文件写入、SSH 用户修改等破坏性动作没有在测试宿主机执行；此次保留原有业务实现，仅迁移整体 UI 样式系统与防火墙链路。
